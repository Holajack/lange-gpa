# Phase 5 — Widening Understanding — App Implementation Blueprint

Grounded in `research/knowledge-base/phase5.md` (Thomson's "Another 500 Hours" guide), `app-implementation.md`, and `nurturer-side.md`. Phase 5 = hours 1000–1500, 500h, target ~10,000-word comprehension vocabulary, 7 activities (`p5-record`, `p5-tensteps`, `p5-retell`, `p5-library`, `p5-media`, `p5-epic`, `p5-community`), currently 6 of 7 have no `practiceHref` and none are reachable anyway because `executablePhase = phase.id === 1` locks every phase but 1 behind "Method preview." This blueprint assumes Phase 1 fidelity work (see `phase1-completion-plan.md`) lands first and the `executablePhase` gate eventually opens phase-by-phase.

**The one-sentence identity of this phase, never to be lost in feature design:** Phase 5 is not "practice with a person" — it is *making unaccommodated native-to-native speech (recorded WITHOUT the grower present) comprehensible through a paid mentor's clarification*, so the grower stops being capped by foreigner-directed speech and starts understanding host people talking to each other.

---

## 1. Core feature mapping

### 1.1 The Ten-Step Discourse Session (`p5-tensteps`) → the phase's live-session-room analog

**What the guide prescribes (§2.2–2.3):** a 2-hour "supercharged participation meeting" with a fixed shape — small talk 5–10 min → GP retells yesterday's clarified portion → clarify a NEW 5–10-min segment together (80–90 min total, looping across multiple segments) → 20–30 min supercharged talking activities. Ratio: ~1 clarifying hour per 20 min of recording (~3h total work per recording-hour).

**Concrete feature — "Clarifying Room" (a new room type, sibling to `/session`, not a retrofit of the Dirty Dozen room):**
The existing `/session` room is architecturally a Phase-1 machine: fixed 12-card deck, `sessionFlow.ts` state machine built around reveal/review of *vocabulary items*, countdown-drives-review-sweeps. None of that maps onto Phase 5's actual unit of work, which is a **segment of a real audio recording**, not a card. Rather than force-fit `sessionFlow.ts`, Phase 5 needs its own state machine — `clarifyFlow.ts` — that mirrors the *shape* of the existing one (pure-state-transition, countdown-timer-owns-the-clock, single source of truth for stage) but operates on segments instead of cards:

- **Stages:** `pre` (small-talk prompt shown, mirrors the join card) → `smalltalk` (5–10 min, optional skip) → `retell-yesterday` (if a prior segment exists in this discourse's history, GP retells it — recorded) → `clarify` (the 80–90 min core loop, segment by segment) → `talking-activity` (20–30 min, picked from §6.8's list) → `end`.
- **Grower's view during `clarify`:** an audio scrubber loaded with the current 5–10-min segment (not a 12-card grid — Phase 5 has no picture cards, it's Thomson's own resource table: "Phase 5: Recordings of host to host speech"), a **big Play/Pause/Rewind-15s** control (mirrors the guide's "pause every phrase or two, rewind, replay" mechanic), and a **"I don't understand" button** that logs a timestamp + optional voice-memo of the mishearing (the guide's precise confessions: "hocus?" for *focused*) — this becomes the seed of the word recording.
- **Mentor's view during `clarify`** (mirrors the Nurturer Studio's amber "mentor only" tray pattern from `/session`): the same scrubber, plus a **word-elaboration prompt card** that appears whenever the GP flags a word — NOT a blank text box, but a structured coax: "Where did this occur? What's a second context? Is there a register note?" (directly encodes §3's finding that mentors need coaxing to elaborate rather than bare-define — "Often you will find that you have to coax the elaborations of new words out of the mentor"). A **"repeat slowly" button** that just replays the segment at 0.7x (mirrors the sessionFlow AI-mode's existing 0.7-rate repeat pattern already built for Phase 1) gives the mentor a low-friction way to do the guide's #1 mentor move without needing her own equipment.
- **What gets recorded:** four separate audio tracks per meeting, matching §9.2 exactly — (a) the GP's Step-3/4 initial summary + mentor's response, (b) the clarified segment discussion itself, (c) the **word recording** (one clip per flagged word, auto-boundary-detected from the flag timestamps), (d) the closing retell (Step 10). All four feed the Listening Library (§5 below), not just a generic session log.
- **What gets tracked:** minutes clarified, recording-hours consumed (for the 3:1 ratio dashboard, see §5), words flagged → later promoted to the word recording, and — critically, unlike the Phase-1 room's synthetic `live-${nurturerId}-${n}` id — this DOES tick `p5-tensteps` in `completed` plus feed a phase-specific `discourseLog` (segment count, source recording id, mentor id, date) so retellings (`p5-retell`) know what "yesterday's portion" was.

**Meeting length:** the guide's 2-hour skeleton doesn't fit the existing 30-min Meeting Timer at all. Rather than force Phase 5 into the same fixed 30-minute (5/20/5) shape flagged as wrong even for Phase 1 in the completion plan, the Nurturer Studio needs a **Phase 5 meeting template**: 5-10' small talk / 5' retell / 80-90' clarify / 20-30' talking = a real ~2h block, selectable in the Session Planner once `phase=5` is chosen (today the planner caps at 60 min regardless of phase — this is a `phase1-completion-plan.md` M13-adjacent gap that Phase 5 inherits and makes worse, since its native unit is 2 hours not 30–60 minutes).

### 1.2 Collect Native-to-Native Recordings (`p5-record`) → a Recording Pipeline dashboard, not a "practice" screen

**What the guide prescribes (§2.1, §9.1):** the grower does NOT make these recordings — hosts do, with the grower explicitly absent ("so that it will be told by a host person to a host person with no thought of accommodating a newcomer"). Two acquisition patterns: Option A (hired life-story interview of a stranger, using a past Phase-4 interviewee as interviewer), Option B (hot-topic discussion among 2–3 acquaintances). Target ~1 hour, 20-min minimum, per discourse. Consumption rate ~20 min recording per meeting-hour → ~5h/week of fresh recording needed at full intensity.

**Concrete feature — "Recording Requests" board:**
- Grower posts a **collection request** (Option A or B template pre-filled with the guide's own instructions: "Do not be present. Aim for 1 hour, 20 minutes minimum."), assignable to (a) a paid mentor/collector from the marketplace, (b) a trusted host contact via a shareable link (no app account needed — records on their own phone, uploads via a link, since the whole point is the grower never touches this step), or (c) a community "recording pool" contributed by other growers/graduated GPs in the same language (§4.1 of the guide: "hopes GPs bequeath collections to those who come after").
- Each collected recording gets metadata the clarify room depends on: duration, **stranger vs. intimate** difficulty tag (the guide's explicit early→late ladder, §7.1), topic/hot-topic tag, source type (Option A/B/movie/broadcast).
- A **recording-hours ledger** ("You have 3h20m of uncleared recording queued, ~10 meeting-hours of clarifying ahead of you") makes the 3:1 ratio and the 100–125-hour phase target (§2.6, §9.1) visible and actionable rather than an abstract guide fact.
- This is explicitly NOT a "listening practice" screen (the current `kind: listening, minutes: 30` encoding in `phases.ts` mischaracterizes it per the KB's own delta note #5) — it's a logistics/coordination surface.

### 1.3 Next-Day Retelling (`p5-retell`) → built into the Clarifying Room's `retell-yesterday` stage (see 1.1), NOT a standalone screen
The guide treats this as the meeting's warm-up, not an independent activity — folding it into `clarifyFlow.ts`'s stage sequence (rather than a separate practice route) is more faithful than the current flat activity-list treatment, and it's also how the grower's spoken output naturally gets a recording for §6.9 (Record Yourself for Feedback) to hang off later.

### 1.4 Listening-Library Review (`p5-library`) → the phase's daily home-practice surface
**What the guide prescribes (§2.4, §9.4):** same-evening re-listen to the day's clarified portion + word recording, PLUS rotating re-listens to older clarified recordings and older word recordings, growing to cover the whole accumulated library "periodically." The **shrinking-copy technique** (§9.3): make a copy of the word recording, delete entries as words become "highly familiar," so review time concentrates on the stubborn residue.

**Concrete feature — "Listening Library" tab** (grower-facing, phase-5-specific but architecturally the first instance of a pattern every later phase will also need — see §5):
- A scrollable list of every clarified recording + its word recording, tagged by date and discourse.
- **Tonight's Queue**: auto-populated with today's clarified segment + today's word recording (the "same evening" rule), plus 1–2 older items surfaced by a spaced-repetition-style rotation (not literal SRS scheduling of vocabulary items — the guide never prescribes flashcard SRS, it prescribes *whole-recording* re-listening — so the rotation picks whole recordings/word-recordings, weighted toward ones not re-heard recently).
- **Shrinking-copy mode** on any word recording: after playback of a word entry, a "mark as familiar" swipe removes it from the NEXT play-through of that copy (never destroys the original) — this is the single most concretely portable mechanic in the whole phase guide (the KB's own delta note #2 flags it as "arguably the most app-able mechanic in the whole guide") and it's a natural fit for the existing `IcebergToast` visual language already built for Phase 1 misses.

### 1.5 Clarify a Movie or TV Drama (`p5-media`) → a variant clarify-room mode, not a separate 45-min activity
**What the guide prescribes (§2.5):** same 2-hour skeleton, but the centerpiece talking activity is reversed — the GP does exhaustive **detailed observation and description** of what they see on screen (visual channel treated as "an illusion" you must describe and have interpreted, never assumed understood), and the mentor supplies the insider's read. Caution: "often the mentor is not seeing what you are seeing" — dubbed foreign films are second-choice.

**Concrete feature:** `clarifyFlow.ts` takes a `sourceType: "audio" | "video"` flag. In video mode, the `talking-activity` stage defaults to a **"Describe What's Happening"** sub-mode: video pauses at intervals, grower types/speaks a description into a recorder, mentor's response (audio) is captured alongside it. This reuses the existing `p2-describe`/`/practice/speaking` recording pattern conceptually but needs the paired video timestamp, which no current practice game has.

### 1.6 Supercharged Talking Activities (§6.8) → an activity picker inside the Clarifying Room's `talking-activity` stage
Only Epic Storytelling (`p5-epic`) has a `practiceHref` today, and per the KB delta it's mis-modeled as a single native-length narration rather than the guide's actual "grown a bit each day, retold to several helpers" iterative loop. The other five (picture discussion/hole-finding, teach-your-specialty, opinion defense, ongoing topic discussions, talks/lectures) should be **prompt cards surfaced inside the 20–30 min stage**, each producing a Record-Yourself-for-Feedback clip (§1.7). This keeps them from being 6 more disconnected `phases.ts` rows with no game behind them — they become one well-built stage with a rotating card deck, matching how the Nurturer Studio's card table already works for Phase 1 vocab.

### 1.7 Record Yourself for Feedback (§6.9) → cross-cutting capture, not its own screen
Every talking activity and every retell in Phase 5 should route through one shared "record → mentor flags non-host-like features" capture component (this already exists for Phase 4 as `p4-feedback` / `/practice/speaking`'s recording pattern) rather than being invented fresh here — Phase 5 mostly needs the mentor-facing annotation UI (tag a clip timestamp + short note) that Phase 4 doesn't yet have either (per `nurturer-side.md` §7, Phase 4 also lacks this).

### 1.8 Join a Community of Practice (`p5-community`) → status/progress tracker, not a game
The guide describes a real-world social embedding (work group, club, class, mosque/church, teashop regulars) that gradually flips the grower from "outside guest" to "valued belonger" — this is fundamentally not simulable and the app's job is logging + reflection, not gameplay:
- A simple **community log**: name the group, log attendance hours (counted toward the 500 with the guide's own 100–200-hour cap on ordinary-social-hours, §2.6/§7.3), and a periodic self-rated **guest → belonger** slider with a prompt ("What did you understand today that you wouldn't have three months ago?"). This is reflection tooling, matching the "N9. Gap-filling journal" pattern already flagged as low-effort in the Phase 1 plan — reuse that pattern here rather than inventing a new journal type.

## 2. Solo / AI-partner fallback design

The honest split, activity by activity:

### Can authentically substitute (comprehension drilling / re-practice of already-clarified material)
- **Listening Library re-listen + shrinking-copy review (§1.4).** This is ALREADY solo by design in the guide itself — no fallback needed, it IS the solo mode. The AI's only role here is UX: surfacing the queue, running playback, tracking familiarity marks. No Nuri persona needed.
- **Word recording review / vocabulary re-encounter.** Reusing the existing `/practice/repeat` "Re-live Your Words" pattern (already 100% solo, auto-advancing listen → say-aloud → re-listen) for Phase 5's own harder, lower-frequency word set is authentic — the guide's Iceberg Principle (§6.4) explicitly wants "massed re-encounters," and solo repetition of a word recording clip IS a real re-encounter, not an imitation of one.
- **Solo pre-clarifying (§2.1).** The guide itself prescribes this as solo, pre-meeting work: phrase-by-phrase listening with pauses, before ever seeing a mentor. Nuri's role: a **pacing tool**, not a conversation partner — pause/rewind controls with a "how much did you understand?" self-rating logged as the Step-2/3 summary the mentor will later respond to. No AI dialogue required; this is a media player with instrumentation.
- **Rehearsal for talking activities (opinion defense, teach-your-specialty, lecture practice, §1.6).** An AI CAN roleplay a listener/prompt-giver for **rehearsal purposes only** — Nuri-the-AI, in the language sibling voice already built for Phase 1, asks a topic-appropriate prompt ("Tell me about your profession — I don't know anything about it") and lets the grower practice the monologue solo before delivering it live. This is explicitly framed to the grower as *rehearsal for the real mentor conversation*, never a substitute for it — the guide's talking activities exist specifically because "important to your continued growth" happens against a real host person's real reactions and corrections, which an AI's canned prompts cannot supply.
- **Epic Storytelling increments, solo drafting.** The GP can record today's increment alone, then have Nuri prompt "tell me more" (mirrors §6.2 Expanding) as a placeholder audience before the increment is retold to an actual mentor/friend per the guide's real mechanic (retelling to several separate helpers who interact and help).

### Cannot authentically substitute — say so plainly, and here's the honest bridge
- **Clarifying a native-to-native recording (the core engine, §6.1).** This is structurally impossible to fake with AI in the way the phase requires, for two independent reasons: (1) the source recording itself must be real native-to-native speech collected with the GP absent — an AI generating "native-sounding" dialogue and calling it a native-to-native discourse would be synthetic content masquerading as ethnographic reality, exactly the "cheap imitation" the task brief warns against, and it would teach the grower a statistically-averaged AI register rather than the actual unaccommodated speech patterns of real host people; (2) even given a real recording, the elaboration a mentor gives (contexts from her own life, register judgments like "it sounds fancy, they're on national television," decisions about when to punt on a hard word) comes from lived membership in the host culture that an AI does not have and cannot honestly claim to have.
  - **What the AI bridge offers instead:** when no mentor is available, Nuri can run the **mechanical parts** of clarifying without inventing the missing cultural judgment — replay controls, a dictionary/glossary lookup for words the grower flags (clearly labeled as a *dictionary definition*, not a mentor's contextual elaboration, so the grower never mistakes a flat definition for the real thing), and a queue that holds the flagged words for the NEXT real mentor session ("You had 14 unclear moments in this segment — bring these to Sofia on Thursday"). This keeps solo time useful (comprehension attempts, self-scoring, question-generation) while being explicit that the grower is *preparing* for clarification, not receiving it.
- **Collecting native-to-native recordings (§9.1).** By definition requires real host people talking to each other with the GP and any AI proxy structurally absent from the interaction. No AI role here at all — this is pure human-sourcing, which is why §3 below (Finding real participants) is so central to this phase specifically.
- **The mentor's real small talk / relationship (§2.3 opener, §3 mentor behavior).** An AI can prompt the grower with reflection questions ("What do you want to ask your mentor about her life today?") but cannot BE the relationship — the guide is explicit that growth happens through "growing into the lives of individuals," and a canned AI persona sharing fabricated "worries about her country's future" would be a hollow imitation of exactly the kind of genuine personal disclosure the guide's own worked example centers on.
  - **Bridge:** a **pre-session prompt generator** — Nuri suggests 2–3 genuine small-talk openers based on what the grower knows so far about their actual mentor (pulled from message-thread history, §4 below), priming a better real conversation rather than replacing it.
- **Community of practice belonging (§6.13).** Cannot be simulated at all — it is real embedded social status in a real human group. AI's only honest role: the reflection/logging tool in §1.8, nothing performative.
- **Movie/TV clarifying's insider interpretation (§2.5, §1.5).** The mentor's "insider's view" on a scene is exactly the kind of host-world-specific judgment (§5 of the guide: "often the mentor is not seeing what you are seeing") that an AI cannot supply without inventing culturally unverified claims. Bridge: the grower can still do the solo "detailed observation and description" half alone (record a description of what they see, flag uncertain parts) — genuinely useful hole-finding practice per the guide's own framing — but the AI must NOT attempt the interpretation half; it should visibly queue those flagged moments for the next real mentor session rather than fabricate an answer.

**Design rule to encode in the UI itself:** every AI-mode screen in Phase 5 should carry a visible distinction the app doesn't currently have anywhere — a "rehearsal / prep" badge vs. a "with your mentor" badge — so growers are never confused about which mode they're in. Phase 1's AI mode (Nuri running the identical sessionFlow as a human) works because Phase 1's content (concrete vocabulary, TPR) is genuinely AI-substitutable; Phase 5's is a fundamentally different mix and the UI must say so.

## 3. Finding real participants for this phase

The helper role here is the **paid mentor** (§3 of phase5.md: "you typically meet with a paid mentor for the sake of clarifying such recordings" — untrained, natural-communication, unlike the trained Phase 1–3 nurturer). Two distinct sourcing needs exist in parallel: (a) a clarifying mentor for the 2-hour sessions, and (b) recording collectors/hosts for the native-to-native source material — these can be the same person or different people.

### 3.1 Marketplace evolution: from "nurturer roster" to "mentor + collector roster"
`src/lib/nurturers.ts`'s 17-person demo roster already has `phasesGuided` (mostly "1–2", max "3–4") and `methodCertified` — but `methodCertified` is the WRONG signal for Phase 5. The guide is explicit: "the mentors do not need training, as the communication is natural." A Phase-5 mentor doesn't need the golden-rules certification that gates the Nurturer Studio today (per `nurturer-side.md` §7, "nothing stops a Phase-1-certified nurturer from being booked at any phase" — for Phase 5 that's not just a gap, it's the WRONG axis of quality entirely). What actually matters for a Phase 5 mentor, per the guide's own worked example (§3): willingness to elaborate rather than bare-define, comfort being coaxed, patience with rewind/replay, and — separately — literacy (to write word lists) if the language is written.

Concrete marketplace changes:
- Add a **`mentorTraits`** field distinct from `methodCertified`: `{ elaboratesWell: boolean (crowd-rated), literate: boolean, comfortableBeingRecorded: boolean, availableForRecordingCollection: boolean }`. Populate via post-session ratings from growers (a simple "did she explain words with examples, or just define them?" prompt after each clarify session) rather than a one-time quiz — this matches the guide's own framing that mentor quality is observed through interaction, not certified through a test.
- Add a **`phasesGuided` upper bound that actually gets used for matching** (flagged as unused today in `nurturer-side.md` §7's "Marketplace honesty" gap) — surface mentors whose `phasesGuided` includes "4–5" or "5" prominently in Phase 5's marketplace view, and visibly deprioritize (not hide — a Phase 1–2 nurturer COULD still collect recordings even if she's not ideal for clarifying) mentors with no Phase 4–5 experience.
- Add a **"Recording Collector" role tag**, separate from "Clarifying Mentor" — someone who's good at arranging Option A/B recordings (knows talkative people, comfortable running a 1-hour recorded conversation) doesn't need to be the same person who sits with the grower for 2 hours of clarifying. This directly powers the Recording Requests board in §1.2.

### 3.2 Paid vs. exchange-hours — different from Phase 1's model
Phase 1's marketplace already carries `ratePerHourUsd` (PPP-scaled $4–14) alongside `exchangeOpen` (time-for-time). The guide's own language for Phase 5 mentors is "typically paid" — but there's a specific incentive-structure wrinkle Phase 1 doesn't have: **recording collection is a discrete, deliverable-based task** (one finished 20-min-to-1-hour recording), not an hourly relationship. This argues for a **two-sided payment model** on the same roster:
- Clarifying meetings: hourly, same wallet/ledger mechanism already scaffolded in `convex/schema.ts` (`wallets` with `exchangeHours`/`paidHours`, `ledger`) — though `credits.ts`'s `recordEntry` currently throws pending a verified session/payment event, so Phase 5 (like every other phase) is blocked on that same infrastructure work, not something Phase 5 needs to solve itself.
- Recording collection: **per-deliverable bounty** ("$X for a 30+ minute Option-B hot-topic recording, GP-verified-absent"), which is a genuinely new payment shape not currently modeled anywhere in the schema — flag as new infra need (§5).
- Exchange-hours: workable for clarifying (a fluent bilingual host person clarifying in exchange for reciprocal help in their own target language, same as Phase 1's `exchangeOpen`), but awkward for recording collection specifically, since the "helper" in that case is often not the grower's conversation partner at all but a stranger paid to talk to another stranger — exchange-hours don't naturally fit a three-party transaction. Default recording-collection to paid/bounty only; keep exchange-hours available for clarifying-mentor relationships.

### 3.3 Verification specific to this phase's structural requirement
The guide's hardest rule — the GP must NOT be present during recording — is also the hardest thing to verify remotely. Concrete design: recordings submitted through the Recording Requests board (§1.2) require the collector to self-attest absence ("I confirm the grower was not present or listening during this recording") as a hard gate before the file can be attached to a session, plus a lightweight **peer-review flag** other growers/mentors in the same language pool can raise if a submitted recording sounds obviously accommodated (over-enunciated, foreigner-directed cadence) — soft social verification rather than unverifiable technical detection.

### 3.4 Community/volunteer sourcing beyond the paid marketplace
Per the guide's own hope (§4.1: "those who come after her will indeed be this fortunate, having Li Fang's recordings to make use of") — a **shared recording commons per language**, opt-in, where growers who've finished clarifying a discourse can donate the now-thoroughly-clarified recording + its word recording to a language-wide pool for future growers to draw on (with the original collector/mentor's consent, since these are real people's real conversations). This is the single highest-leverage sourcing feature for minority languages where the 5h/week fresh-recording logistics genuinely can't be sustained by every individual grower — matches the guide's explicit acknowledgment that this is "a challenge" and its "possibly starting collection in Phase 3/4" suggestion, which argues the commons pool should start accepting donations before Phase 5 even begins.

## 4. Pen-pal-style relationship growth

Build directly on `convex/messages.ts` (1:1 threaded text + voice notes, `convoKey` = sorted clerk-id pair, 30 msg/60s rate limit, blocked-pair checks) and `convex/requests.ts` (Tandem-style session requests). Nothing here reinvents messaging — it layers Phase-5-specific structure and prompts ON TOP of the existing thread.

### 4.1 What makes this Phase-5-specific, not generic chat
The guide's own Phase 5 opener line IS the design brief: *"Find out what is important to your mentor today. Learn some things about her life that are new to you. Share something of interest about yourself."* — and its rationale: *"You grow into the life of an ethnolinguistic group by growing into the lives of individuals in it."* That's a relationship-depth mandate, not a scheduling mandate. Concretely:

- **Between-session async continuity thread**, one per grower↔mentor pair, using the existing `messages` convoKey pattern unchanged. What's new is a **Phase 5 discourse-context header** on the thread: the last clarified recording's topic, the last word flagged as puzzling, the last "tell me more about X" the grower asked — auto-populated from `clarifyFlow.ts` session logs (§1.1) so the thread isn't blank the next day, it opens already knowing what the pair was in the middle of.
- **"What are you thinking about?" as a standing async prompt**, not just a live-session opener: once a week, the app nudges BOTH sides with the guide's own opener line as an optional voice-note prompt — sent async via the existing `sendVoice` mutation, no live session required. This turns the guide's 5–10-minute in-meeting small talk into an ongoing between-meetings thread, exactly the "pen-pal" ask — the relationship doesn't pause between the (expensive, scheduled) 2-hour clarifying meetings.
- **Word-recording follow-ups as conversation starters**: when a word gets flagged mid-clarify and the mentor's elaboration was thin (the guide's own "coax the elaboration" problem, §3), the app can queue a gentle async follow-up the NEXT day: "Yesterday you mentioned 'sexist' was too complicated to explain — want to try again over text, or save it for next time?" This uses the existing voice-note channel to let elaboration continue asynchronously when live time runs out, which happens constantly in the guide's own worked example (mentor punts on hard words for time).
- **Retelling exchange**: the GP's Step-10 whole-discourse retell (recorded in the clarify room) can be sent to the mentor via the message thread for async feedback — voice note in, voice note back — extending "retelling by the mentor, use 2" (host-like model, §6.7) into homework-time rather than requiring it to happen live.
- **Relationship depth indicator** (soft, non-gamified): a simple thread metadata line — "6 clarifying sessions together · 3 async check-ins this month" — visible to the grower, giving light social proof that this mentor relationship is deepening, without turning it into a points/streak mechanic that would cheapen what the guide frames as a genuine bond.

### 4.2 What this deliberately does NOT do
No group chat, no public feed, no gamified streaks — the guide's relationship-building in Phase 5 is explicitly pair-based (one grower, one mentor, growing mutual knowledge of each other's actual lives), matching `messages.ts`'s existing 1:1-only design. Community-of-practice belonging (§1.8, §6.13) is a SEPARATE, group-shaped growth track and should not be conflated with the mentor pen-pal thread — they serve different parts of the methodology (individual relationship depth vs. group social status) and merging them would blur both.

## 5. Dependencies & shared infrastructure

### What Phase 5 needs that Phase 1 doesn't have yet
1. **A recording-segment-based state machine** (`clarifyFlow.ts`) distinct from the card-based `sessionFlow.ts` — Phase 5's unit of work is a timestamped audio segment, not a vocabulary card; forcing it into the existing deck/review model would be a structural mismatch, not a reskin.
2. **A Listening Library data model and UI** (§1.4) — accumulating, taggable, periodically-rotated audio recordings with a shrinking-copy review mode. Nothing like this exists; the current Phase 1 room only offers a single downloadable clip.
3. **A Recording Requests / collection-pipeline board** (§1.2) — third-party (non-grower, non-mentor-in-session) recording submission, with GP-absence self-attestation and peer review.
4. **A per-deliverable bounty payment shape** in the wallet/ledger schema, alongside the existing hourly `paidHours`/`exchangeHours` — recording collection is a discrete deliverable, not an hourly relationship.
5. **A mentor-quality signal separate from `methodCertified`** — crowd-rated elaboration quality, literacy, recording-collection availability — since Phase 5 mentors are explicitly NOT trained/certified the way Phase 1–3 nurturers are.
6. **A discourse-context header on message threads** — auto-pulling the last clarified segment/flagged word into the async thread so pen-pal continuity doesn't require the grower to manually recap.

### Shared infrastructure phases 2–6 almost certainly need together (design once, not six times)
- **Generic async 1:1 relationship thread with phase-aware context headers** — every phase from 2 onward has SOME helper relationship that should deepen between sessions (Phase 2/3 nurturer, Phase 4 mentor/life-story confidant, Phase 5 mentor, Phase 6 discourse coach). Build the "discourse-context header on top of `messages.ts`" pattern from §4.1 generically, parameterized by phase, rather than as a Phase-5-only feature.
- **A generic Listening Library / recording-and-relisten system.** Phase 2 already needs this (clarifying-the-recording, word–sentence–word recordings), Phase 3 needs it (Bridge Story recordings, host stories), Phase 4 needs it (life-story recordings, expansion recordings), Phase 6 needs it (Record-for-Feedback improved-version recordings). Building it Phase-5-specific would mean rebuilding it four more times; the shrinking-copy review mode and same-evening-queue logic in §1.4 should be designed as a shared primitive from the start.
- **A generic "helper role" abstraction that isn't hard-coded to `nurturer`.** The codebase's `role: "grower" | "nurturer"` string and the `Nurturer` type are Phase-1-shaped. Phases 4–5 need "mentor" (untrained, natural, often paid) and Phase 6 needs "discourse coach/subject professor" (a different skill profile again) — these aren't cosmetic renames, they're different quality signals, different verification needs, and different certification-or-lack-thereof. A shared `HelperProfile` type with a `helperRole: nurturer | mentor | community` discriminant, feeding phase-appropriate marketplace views, avoids re-solving "how do we find and vet this phase's helper" from scratch six times.
- **A generic recording-collection/bounty pipeline.** Phase 5 needs GP-absent native-to-native collection; Phase 6 needs "record the same materials the grower reads, discussed on recording" and expert-interview-style collection. The submission/attestation/peer-review shape from §1.2/§3.3 generalizes.
- **A per-deliverable payment/bounty ledger shape**, alongside the existing hourly ledger — likely needed wherever a phase requires a discrete artifact (a recording, a written word list, a life-story transcript) rather than a bookable hour block.
- **A mentor/helper quality-signal system driven by post-session ratings**, not one-time quizzes — replacing or supplementing `methodCertified` for every phase past 3, since "no training needed, communication is natural" is the guide's own stated model from Phase 4 onward.
- **A real credit-earning event pipeline** — `credits.ts`'s `recordEntry` throws today pending "a verified session or payment event." Every phase's paid-mentor economics (Phase 5 clarifying, Phase 5 recording bounties, Phase 6 discourse-coach fees) is blocked on this same missing piece; it's Phase-1-and-earlier-agnostic infrastructure that unblocks the whole marketplace.

## 6. MVP cut

The smallest slice that is still authentically GPA (real native-to-native material, real mentor clarification, no faked "AI native speech") and still delivers all three owner asks (matching / solo-fallback / pen-pal):

1. **One real feature per ask, thinly built:**
   - *Matching:* extend the existing marketplace roster with a `helperRole: mentor` filter and a single new field, `elaboratesWell` (crowd-rated post-session, not pre-certified) — reuses 90% of the existing `/marketplace` UI and `Nurturer` type, no new backend table.
   - *Solo fallback:* ship ONLY the Listening Library + shrinking-copy review (§1.4) as the solo mode — it's the one piece of Phase 5 the guide itself already designs as solo, so it requires no dishonest AI-substitution framing at all, and it reuses the existing `IcebergToast`/repeat-practice visual language almost unchanged. Skip AI-roleplay rehearsal (§2, "can substitute" tier) for MVP — nice-to-have, not load-bearing.
   - *Pen-pal:* ship ONLY the discourse-context header on top of the existing `messages.ts` thread (§4.1) — a few auto-populated lines pulled from the last clarify session's log, no new schema, no bounty/payment complexity yet.
2. **One real clarifying flow, manually seeded:** build `clarifyFlow.ts` and the Clarifying Room (§1.1) end to end for ONE discourse type (Option B hot-topic discussion is simpler to source than Option A's stranger-life-story format) — skip the movie/TV variant (§1.5) and the talking-activity picker (§1.6) for v1; a bare 80–90 min clarify loop + a 5-min retell stage is a legitimate, if narrow, first cut.
3. **Recording sourcing stays manual for MVP:** skip the Recording Requests board (§1.2) and the shared-commons pool (§3.4) initially — let the grower/mentor pair upload one pre-arranged recording (collected off-app, per the guide's absence rule, verified by a simple checkbox) directly into the Clarifying Room. This defers the bounty-payment and peer-review infrastructure (§5) without breaking methodological authenticity, since the RULE (GP absent) is enforced by the same self-attestation checkbox either way — only the discovery/sourcing UX is deferred, not the fidelity.
4. **Explicitly deferred to post-MVP:** the word-recording shrinking-copy's cross-session library scale-up, the community-of-practice tracker (§1.8 — genuinely low-risk to defer since it's pure reflection tooling with no dependency chain), the 3:1 recording-hours dashboard, and all payment/bounty infrastructure.

This MVP is deliberately narrow rather than shallow-across-the-board: one real clarifying loop with one real recording, a real (if thin) mentor-quality signal, a real solo-listening bridge that doesn't fake the human part, and a real async thread that remembers yesterday's session — every piece is authentic GPA, nothing is a placeholder pretending to be the real mechanic.
